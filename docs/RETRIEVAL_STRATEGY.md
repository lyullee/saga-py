# 검색 정확도 개선 전략

현재 시스템은 FTS5(BM25 계열) 검색과 LLM 재순위화에 의존한다. 2.1부터는 다음을 함께 사용한다.

- FTS5 키워드 검색: 기준번호·조항·정확한 용어에 강함
- 로컬 해시 n-gram 벡터 검색: PDF 추출 과정의 띄어쓰기·조사·OCR 변형에 강함
- 메타데이터 제한: 기준번호와 문서 종류를 먼저 제한
- RRF(Reciprocal Rank Fusion): 두 검색 결과를 하나의 후보 목록으로 통합
- 기존 결정적 안전 규칙: 표·수치·법정 기준은 근거 검증 후 답변

벡터 인덱스는 외부 모델을 다운로드하지 않는 `hash-ngram-v1` 폴백이다. 추후
`multilingual-e5` 또는 `bge-m3` 임베딩 서비스를 연결할 때도 `vector_search`의
반환 형식을 유지하면 검색 계층을 교체할 수 있다.

## 색인 상태 확인

```powershell
python tools/eval_retrieval.py --database data/saga.db
```

평가 결과에서 `document_recall_at_k`가 낮으면 LLM 프롬프트를 수정하지 말고,
문서 코드·메타데이터·청크 경계·표 추출을 먼저 점검한다. `section_recall_at_k`가
낮으면 조항 구조화와 인접 페이지 확장을 점검한다.

## 다음 단계

2. 표를 행·열 구조로 보존하는 PDF 파서를 추가한다.

4. 회귀 평가를 색인·프롬프트 변경 때마다 실행한다.
